# Agent Sessions 改造方案

确认时间：2026-09-30。产品名由用户选定为 Agent Sessions，skill 名为 `agent-sessions`。

## 定位与当前状态

本地 Agent 会话管理与长期上下文应用。以项目聚合 Codex、Claude Code、Antigravity 的会话，共用对话与轨迹视图，支持跨会话搜索和按需找回证据。长期上下文由可检索的本地历史组成，不宣称模型的单次上下文窗口无限。

首版现已实现三种来源的会话、对话和轨迹，跨来源项目聚合与手动映射，以及 Tauri macOS 应用和菜单栏常驻。Claude 工具关联由受控 fixture 验证；Antigravity 的独立结果关联尚无可靠标识，调用与执行记录分开显示。跨会话正文搜索、交接摘要和目录监听仍是后续阶段，不作为本版能力。

现有界面继续复用，移除 DeepSeek 品牌和“选择会话”大按钮。保留组件样式、图标及相应 MIT 声明。原工作目录暂保留，以免打断运行中的服务及现有路径引用；产品名称不再依赖该目录名。

## 本机数据源验证

核查仅访问记录结构和少量样本，不修改任何 Agent 原始记录。

| 来源 | 已确认的本机入口 | 接入策略与未确认项 |
| --- | --- | --- |
| Codex | `~/.codex/sessions/`、`archived_sessions/`、`session_index.jsonl`；现有 Python 解析器 | 抽取为适配器，保持已有引用、按需结果、增量索引和圈选定位语义。 |
| Claude Code | `~/.claude/projects/*/*.jsonl`；本次发现两个顶层会话文件 | 读取 `sessionId`、`uuid`、`parentUuid`、`cwd`、时间戳、消息内容与自定义标题。按消息 UUID 保留分支关系。样本中有用户/助手文字，但没有工具调用样本；需补充真实或受控 fixture 验证 `tool_use.id` 与 `tool_result.tool_use_id`，不能仅凭位置配对。 |
| Antigravity 桌面版 | `~/.gemini/antigravity/conversation_summaries.db`、`conversations/*.db`、`brain/*/.system_generated/logs/transcript_full.jsonl` | 摘要表包含会话标题、工作区 URI、项目 ID、状态与父会话 ID。会话数据库包含步骤表及二进制载荷。transcript 包含用户输入、助手正文、调用名称/参数、步骤状态与错误；独立工具结果、关联标识和历史覆盖完整性尚未验证。 |
| Antigravity CLI | `~/.gemini/antigravity-cli/` 下的相同摘要库、会话库和 transcript 目录 | 与桌面版属于同一 Agent 类型，保留不同来源实例；不要因会话 ID 相同就直接去重。 |

Antigravity 数据库的本次结构检查使用只读 immutable 连接，仅用于可行性核查。实际实时读取应使用能读取 WAL 的只读连接或一致性快照，不能把 immutable 连接用于活动数据库，否则可能遗漏最新写入。不能因为 transcript 存在就宣称完整结果可读；结果缺失时展示该记录的实际能力范围，保留来源入口。

## 统一数据模型与适配器

前端面向统一记录；来源专属解析留在适配器中。无需将现有解析器整体改写为 Rust。

```text
Agent Sessions 窗口与菜单栏
             │
       统一查询与本地索引
       ┌─────┼─────────┐
     Codex Claude Code Antigravity
       │       │          │
    原始会话  原始会话   桌面 / CLI 记录
```

- 来源实例：`provider`、`instance_id`、数据目录、读取能力和解析格式版本。
- 会话：`session_key`、来源会话 ID、项目归属、标题、更新时间、状态、父会话与分支。
- 事件：`event_key`、原生消息/步骤 ID、类型、时间、正文引用、调用 ID、结果引用、父事件、来源位置。
- 能力：是否可读完整对话、调用参数、独立结果、附件、压缩位置及实时更新。UI 根据能力展示，不能编造不同 Agent 没有记录的字段。

统一键由 `provider + instance_id + native_id` 构成；原生 ID 原值另行保存。保留 Codex 原有 `Txxx/Cxxx` 等引用作为兼容别名，已有深链接仍可定位。跨来源同名会话不合并为一条。同一会话的分支、子代理和主轨迹也不平铺成重复消息。

适配器只需实现来源发现、会话目录、事件分页、单事件/结果读取、变更检查；公共层负责跨来源搜索、项目映射和全局事件定位。各来源结果必须按可验证的关联标识匹配；无标识时不按调用顺序猜测。

初期保留现有增量读取机制。新增 SQLite 索引在有统一来源键和清晰缓存失效规则后接入；索引可重建，原始会话是证据来源。工具结果继续按需读取，不因建立统一目录而预加载所有历史正文。

## 项目与界面

左侧仍按项目组织，项目内混合排列不同 Agent 会话。会话旁显示 Codex、Claude Code 或 Antigravity 小标签，支持“全部 Agent”及单来源筛选。打开后仍是“对话 / 轨迹”两页，沿用现有滚动补页与详情设计。

项目目录采用解析后的绝对路径进行匹配。来源中明确的项目归属保持独立；目录相同只是合并候选。一个目录对应多个 Codex 项目时，允许用户指定跨 Agent 映射，不自动猜测。跨工作树目录也不因仓库名字相同而强制合并。手动映射只保存在 Agent Sessions 中。

首版管理动作保持为此应用中的置顶、重命名、归档、恢复和项目映射。向原 Agent 发送消息、创建会话、删除原始会话或恢复运行另作功能设计，不能把本地视图归档误称为原 Agent 已归档。

长期上下文能力沿用“目录 → 相关会话/轮次 → 必要证据”的按需读取方式；新增跨 Agent 检索和带来源引用的交接摘要，避免每次拼接全量历史。

## 桌面包装选择

建议首选 **Tauri 2**，面向常驻菜单栏的本地查看器。它使用系统 WebView，支持托盘和外部程序 sidecar；现有 Python 可打包为随应用分发的可执行程序，无需用户安装 Python。Electron 同样可行，采用 Chromium 渲染，适合需要统一浏览器行为或团队希望只维护 JS/TS 的情况。实际内存、启动速度和包体需用本项目构建实测，不能引用通用数字作保证。

| 事项 | Tauri 2 | Electron |
| --- | --- | --- |
| 界面复用 | 现有 HTML/CSS/JS，需检查 WKWebView 的 Markdown、滚动和拖动表现 | 现有 HTML/CSS/JS，Chromium 行为与现有预览更接近 |
| 常驻与窗口 | Rust 管理窗口、托盘、单实例和进程生命周期 | JS 主进程管理窗口、托盘、单实例和子进程 |
| 现有 Python | 打包为 sidecar | 同样需打包为附带子进程；Electron 本身不会附送 Python |
| 工程代价 | 新增薄 Rust 外壳，保留 Python 业务逻辑 | 新增 Electron 主进程和打包配置，保留 Python 业务逻辑 |

首版应用启动时拉起自有后台服务，等待就绪后打开应用窗口。后台采用动态本地端口，端口由应用管理，用户不再打开浏览器或手动启动服务。现有 `8765` 查看器可留作开发入口，与应用实例区分；生产应用不盲目接管或结束已有服务。

打包 Python 与资源为 sidecar，随架构一起构建；不能硬编码本机 Python、工作目录或开发端口。前端请求通过一层客户端封装，以便后续从内部 HTTP 换成进程通信，不让业务组件依赖传输方式。

菜单栏提供“打开 Agent Sessions”“暂停同步”“登录时启动”“重启后台”“退出”。关闭窗口后继续常驻；明确退出时停止应用自有后台进程；重复启动聚焦已有实例。登录启动为设置中的可选项，不在安装时默认改变系统设置。

后台先监听来源文件/目录变化并增量更新，辅以低频核对。没有窗口打开时暂停界面轮询与 Markdown 渲染；监听仍用于更新轻量索引。后台异常显示实际状态，并能重新启动，不能让空白窗口伪装成正常运行。

macOS 首先交付 `.app` / `.dmg`。本机测试包与可外部分发的签名、公证包分别验收；后者需要发布身份，不作为原型已完成的依据。

官方依据：[Tauri 架构](https://v2.tauri.app/concept/architecture/)、[sidecar](https://v2.tauri.app/develop/sidecar/)、[托盘](https://v2.tauri.app/learn/system-tray/)、[Electron 进程模型](https://www.electronjs.org/docs/latest/tutorial/process-model)。

## 实施顺序与验收

1. **产品改名与方案落地**：界面和 skill 改为 Agent Sessions；移除 DeepSeek 品牌与冗余入口。已完成。
2. **统一来源接口并接入 Claude Code**：以现有 Codex API 为基线提取公共模型，接入 Claude 会话与分支；验证跨来源同 ID、原值、半行写入、增量更新、工具结果关联及项目映射。三种 Agent 不需要同时重写。
3. **Tauri 桌面首版**：先装入已验证的 Codex/Claude 界面，打包自包含后台。实机检查关闭常驻、明确退出、重复启动、后台故障恢复，以及正文/轨迹交互与现有界面一致。
4. **Antigravity 接入**：先落实摘要与对话覆盖，再验证步骤载荷、工具关联和独立结果。分别测试桌面版及 CLI；没有验证的能力不显示成完整支持。
5. **长期上下文增强**：跨 Agent 搜索、项目映射、带来源引用的交接摘要及增量索引；测试摘要能返回原始会话和准确事件。

第一版桌面应用可以先含 Codex 与 Claude Code，避免 Antigravity 的二进制载荷解析阻塞全部桌面功能。若用户要求三种来源一次交付，桌面首版验收应等待 Antigravity 对话与轨迹覆盖检查完成。

## 首版实现与后续边界

实现文件和运行入口见 [desktop-app.md](desktop-app.md)。当前使用可见窗口的定时核对和增量索引；关闭窗口后暂停界面查询，不运行常驻目录监听。应用自有后台随窗口重新打开继续读取，并在明确退出时停止。外部分发签名、公证、跨会话全文搜索和自动交接摘要另行实施。

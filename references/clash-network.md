# Clash Verge 网络接入

网络设置分为 Clash Verge、出口线路和内网访问。订阅、节点更新、TUN 和内核生命周期由 Clash Verge 管理；Agent Sessions 保存账号与具体节点的绑定，管理启动检查及运行中的异常停止。

## 接入与线路

- macOS 自动读取当前用户的 Clash Verge 配置，并优先连接服务模式的用户 Unix socket；Windows 使用配置中的本机控制接口。手动接口只允许 HTTP 回环地址。接口密钥保存在应用自己的 0600 配置中，不回传给页面。
- 当前线路选择来自 Clash 配置内的具体节点，不绑定自动回退或负载均衡策略组。动态 proxy-provider 的节点暂不列入线路选择。
- 保存线路后，由 Clash 内核监听专属 HTTP 入口。入口的子规则将公司域名交给 DIRECT，其余请求固定到绑定节点。后台用量查询使用各自的入口，不切换公共账号策略组。
- 账号环境启动前要求 TUN 开启、规则模式、所选节点存在和应用分流规则生效。启动时才选择 `Agent Sessions · Claude` 策略组，用它承接 Claude 主程序、Helper、内嵌 CLI 及已知服务域名的 TUN 流量。
- 同时运行的受管环境必须使用同一个活动出口；不同节点不能并行启动。一个账号的浏览器和 App 可以共享同一出口。它们的用户目录和登录数据继续独立管理。
- 策略组默认 REJECT；订阅删除节点后，扩展脚本过滤失效入口，保留 REJECT，不自动选择其他节点。节点重名但地址变化仍需通过已有预检和配置的预期 IP 检查。

## 配置保存

只在 Clash Verge 全局 Script.js 的 `BEGIN/END AGENT SESSIONS NETWORK` 标记内维护本应用片段，包装已有 main，保留用户原脚本。片段包括账号监听入口、子规则、专用策略组、公司 DNS 例外及公司域名解析设置；其他配置继续来自用户订阅。

写入前保存原脚本和配置快照，拒绝已有同名非本应用策略组；立即重载失败时恢复脚本。备份位于应用数据目录的 `network-backups/`。撤销公司域名配置时移除本应用添加的 DNS 例外，恢复原有解析策略。Clash 全局脚本需要启用，后续重新激活订阅时会重新生成同一片段。

修改连接、内网或线路需要先停止运行中的受管环境；配置弹窗在运行期间可查看。迁移旧线路保留其 ID，因此账号、浏览器和 App 的已有绑定不变；在成功写入 Clash 后停止旧受管代理。旧账号目录、会话、凭据及其他代理配置不删除。

## 检测边界

运行中每 500 毫秒检查受管环境，Clash 状态缓存最多 1 秒。发现 TUN 关闭、控制接口失联、规则变化、规则模式退出或活动节点改变后停止受影响环境。它属于发现后停止，存在采样与停止时间差，不是系统 Kill Switch。

TUN 模式下 App 连接显示公网目标是正常现象，不能直接判为绕过代理；保留进程连接样本并标记“已采样”，不将它展示为全量流量无泄漏的证明。系统服务、未知辅助程序、Cowork VM 和更新器仍需要独立实机验收。

内网检测分别检查 Clash 的 DNS 查询和系统到目标 443 端口的连通性；不代表用户已登录或业务操作成功。检测域名只接受已配置的公司域名。

## 验证

本次使用真实本机 Clash 读取版本、TUN 和节点列表；使用独立 Mihomo 实例、两个本机上游验证账号入口分流、公共策略组改变后入口保持、关闭 TUN 拒绝启动、不同出口并发拒绝、异常停止、脚本重复执行及订阅节点消失。没有为这些实验登录 Claude 账号或修改用户实际 Clash 配置。

macOS 本机界面和接口已验证。Windows 提供回环控制接口及配置路径分支，未完成 Windows 实机验收。

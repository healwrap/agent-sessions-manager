# Claude 专用节点与 Clash Verge

Clash Verge 管理系统流量、内核和用户自己的订阅。Agent Sessions 独立保存 Claude 单节点、账号绑定和直连设置，通过一个可撤回的全局脚本片段注入节点与规则。切换外部订阅不会删除或替换已保存的 Claude 节点。

## 节点格式

新节点支持 `http://用户名:密码@服务器:端口`、`https://…`、`socks5://…`，无认证时省略用户名和密码。也可粘贴一个 Clash/Mihomo 节点的 YAML 或 JSON；只接受一个节点，不接收整份订阅，不管理订阅更新。依赖外部 `dialer-proxy` 的节点会被拒绝，避免外部策略组变化影响 Claude 出口。

每个节点有固定内部标识、专属本机 HTTP 入口和账号绑定。节点配置及凭据保存在应用数据目录中，注入给 Clash 的脚本与运行配置使用 0600 权限。旧版从 Clash 选择的节点会复制成独立配置，保留线路 ID、账号绑定、环境目录与登录数据。

## 连接与操作

- macOS 自动读取标准 Clash Verge 数据目录，优先使用当前用户服务 socket，兼容配置中的 Unix socket。用户编号和临时目录在本机计算。
- Windows 使用当前用户数据目录，支持配置中的命名管道及新版本用户服务管道；HTTP 回环控制接口仍可手动填写。密钥默认从本机运行配置读取，手动接口也支持自动读取同一 Clash 的密钥。
- 启动时自动准备网络默认开启：Clash 未运行则查找安装位置并打开，等待控制接口就绪，再开启 TUN、切换规则模式并应用专用节点与分流。失败时不启动账号。关闭自动准备后只做检查。
- 系统代理开关直接读取并修改操作系统当前代理，TUN 开关调用内核 API。二者不修改 Verge 的保存偏好；Verge 重新加载其设置时可能改变实际状态，页面按实际状态刷新。系统代理不会随账号启动自动开启。macOS 修改系统代理必要时请求系统管理员授权；代理守卫与目标状态冲突时要求先在 Clash 处理守卫。
- 系统代理实际状态与 Clash 保存的开关分别读取；两者不一致时使用公共 Toast 短暂提示，不占用卡片布局。同一差异在刷新与轮询时只提示一次，恢复一致后再次出现差异才重新提示。Mihomo 控制接口不提供修改 Verge 自身开关的能力，页面不把保存的开启值显示成已经生效。macOS 只读取顶层系统代理字段，避免 VPN 或其他网络接口的嵌套配置覆盖当前全局状态。
- TUN 服务和系统权限仍由 Clash Verge 安装、申请；没有权限时自动准备会报错。不会自动绕过系统授权。

## 分流与恢复

全局 `Script.js` 的 `BEGIN/END AGENT SESSIONS NETWORK` 标记内维护应用片段，保留用户原 main。片段注入独立节点、`Agent Sessions · Claude` 策略组、本机入口、进程/域名规则及 DNS 覆写，不修改订阅源文件或当前订阅选择。写入前备份，内核加载失败恢复原脚本。

首次使用的直连域名和 DNS 默认为空，由用户配置；不从本机历史配置推断公司域名或 DNS。Claude 分流不依赖全局 Merge 中的内容。全局脚本使用 Clash 默认模板、空内容或文件缺失时，应用均可加入自己的片段；原脚本存在则保留，原文件不存在且使用期间没有新增用户内容时，撤回后删除本次创建的脚本文件。

每次 Clash 用另一份订阅生成配置，脚本都会记录这份订阅被覆写前的规则、DNS 和进程查找设置，然后追加我们的节点与规则。停用分流或正常退出应用时，移除片段和专用节点，并恢复当前订阅的原设置；不会拿旧订阅快照覆盖新订阅。应用自动开启的 TUN/规则模式，在仍保持应用设定时一并恢复；用户手动改变的状态不覆盖。停止单个账号保留网络配置，供线路检测与后台用量查询使用。“停用分流并恢复原配置”会暂停后台网络准备，启动账号或手动应用后再启用。

规则优先级：指定直连域名和 DNS 地址 → Claude 进程 → 已知 Claude 服务域名 → 原有 Clash 规则。直连域名支持子域名，不能包含 Claude 服务域名。配置 DNS 后，指定域名、国内域名集合 `geosite:cn` 以及最终 DIRECT 请求使用指定 DNS；国外其他域名保留原解析设置。域名 DNS 策略和流量路由分别生效。

显式代理请求通过自己的本机入口固定到节点；未使用显式代理的 Claude 主程序、Helper、内嵌 CLI 和已知服务域名通过 TUN 命中专用策略组。账号启动时选择该账号的节点；线路检测及后台查询不切换公共策略组。不同出口不能并行启动。

## 备用节点与顺序回退

在节点配置中选择已有节点作为备用，支持添加、移除和调整优先级。备用节点也可以配置自己的备用：例如 A 的备用是 B，B 的备用是 C，实际顺序为 A → B → C；A 另外配置 D 时，顺序为 A → B → C → D。重复经过的节点只尝试一次，不允许自己引用自己、循环引用或引用已删除节点。每个节点最多直接配置 8 个备用，一条展开后的链最多 16 个节点。

这是依次选择不同出口的回退顺序。每次只使用一个节点，不会把这些代理串起来转发流量。绑定节点、登录目录、账号身份和浏览器指纹种子保持不变，运行报告会分别显示绑定节点与实际使用的备用节点。

- 启动时按顺序检查，跳过连接不可用的节点。已经选中的备用会保存在应用数据目录中，后续启动继续使用它，不因主节点恢复而自动跳回。
- 运行中默认“提醒我，由我切换”。也可在绑定节点上启用“连续失败后自动回退”：每轮检查间隔约 20 秒，连续 3 次连接失败后尝试后续节点。检测请求本身有超时，不能保证故障发生后固定多少秒完成切换。
- 切换前单独检测候选节点的出口和 Claude 服务连通性，核对已记录的 IP 与当前国家。通过后才停止并重启使用此绑定节点的环境；当前响应和工具任务可能中断，登录及会话目录保留。其他账号环境正在使用不同出口时阻止切换。
- 首次通过验证的节点记录出口，后续 IP 变化时要求重新确认。供应商确实更换 IP 后，可在节点配置展开“重新确认出口”，选择保存后重新记录；账号固定的主节点 IP 仍需在环境配置中单独确认。自动切换必须有已确认的当前国家；候选国家不同则拒绝。手动语言、时区保留原设置，选择跟随代理的环境会在重启时重新定位。
- 后台用量查询跟随实际选中的备用，切换期间暂停查询，避免账号从主线和备用同时发起请求。
- 所有候选失败时保留当前线路并显示错误，不退到系统直连。列表提供“切换备用 / 继续回退”和“切回主节点”，切回同样先检查再重启。
- 检测网站返回 403/404 等有效 HTTP 响应不算连接超时。节点可连接但出口或地区查询暂不可用时仅提示核对，不计入自动切换的连续连接失败次数。短请求健康不能证明每条长对话连接都健康；对话卡住时仍可手动回退。

备用关系保存在 `environments.json` 的 `fallback_ids` / `fallback_mode` 中；当前选择和已验证出口保存在独立的 `network-fallback.json`，不写入仓库，也不复制代理凭据。

## 检查边界

启动时检查控制接口、TUN、规则模式、分流和节点，再执行代理及出口 IP 门控。固定节点不代表固定 IP，填写预期 IP 后才执行指定 IP 比对。浏览器有目标窗口出口采样，App 的启动 IP 项来自后台代理探针。

运行中每 500 毫秒检查网络状态，状态缓存最多 1 秒；TUN、模式、规则或节点异常后停止环境。App 进程连接目标采样间隔 250 毫秒。TUN 下公网目标 IP 不等于绕过代理，目前未逐连接核对 Clash 链路；发现后停止存在时间差，不是系统 Kill Switch。

强制结束进程、断电或 Clash 控制接口失联时无法承诺完成运行配置恢复；下次启动会清理残留的应用片段，Clash 正常重新加载也会使用可撤回的脚本配置。

直连域名检测仍只检查已配置域名的 Clash DNS A 记录及系统 TCP 443 连通性，不核对完整网页或实际命中链路。

## 验证范围

macOS：本机接口、实际代理状态读取和界面可验证。独立 Mihomo 实验验证单节点入口、公共策略组隔离、外部订阅无相同节点时的重新注入、当前订阅恢复、脚本撤回与加载失败回退。模拟 TUN 状态验证自动准备、取消和阻断路径，避免创建第二个系统 TUN。

Windows：具备配置路径、安装查找、命名管道、系统代理和 HTTP 连接实现；尚无 Windows 实机验收。

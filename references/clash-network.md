# Clash Verge 网络接入

网络设置分为 Clash Verge、出口线路和直连配置。订阅、节点更新、TUN 和内核生命周期由 Clash Verge 管理；Agent Sessions 保存账号与具体节点的绑定，管理启动检查及运行中的异常停止。

## 接入与线路

- macOS 自动读取当前用户的 Clash Verge 配置，并优先连接服务模式的用户 Unix socket；Windows 使用配置中的本机控制接口。手动接口只允许 HTTP 回环地址。接口密钥保存在应用自己的 0600 配置中，不回传给页面。
- 当前线路选择来自 Clash 配置内的具体节点，不绑定自动回退或负载均衡策略组。动态 proxy-provider 的节点暂不列入线路选择。
- 保存线路后，由 Clash 内核监听专属 HTTP 入口。入口的子规则将直连域名交给 DIRECT，其余请求固定到绑定节点。线路检测和后台用量查询使用各自的入口，不切换公共账号策略组。线路的“已选节点”表示该策略组当前选项；账号实际出口以环境检测结果为准。Clash 连接信息只展示内核版本和本机连接方式。
- 直连配置适用于指定域名，不限于公司内网。直连 DNS 可选：填写后，国内域名集合 `geosite:cn`、指定直连域名和最终走 DIRECT 的请求使用这些服务器；国外域名保留 Clash 原有 DNS。留空恢复原有解析设置。Claude 服务域名不能加入直连。
- 账号环境启动前要求 TUN 开启、规则模式、所选节点存在和应用分流规则生效。启动时才选择 `Agent Sessions · Claude` 策略组，用它承接 Claude 主程序、Helper、内嵌 CLI 及已知服务域名的 TUN 流量。
- 同时运行的受管环境必须使用同一个活动出口；不同节点不能并行启动。一个账号的浏览器和 App 可以共享同一出口。它们的用户目录和登录数据继续独立管理。
- 策略组默认 REJECT；订阅删除节点后，扩展脚本过滤失效入口，保留 REJECT，不自动选择其他节点。节点重名但地址变化仍需通过已有预检和配置的预期 IP 检查。

## 配置保存

只在 Clash Verge 全局 Script.js 的 `BEGIN/END AGENT SESSIONS NETWORK` 标记内维护本应用片段，包装已有 main，保留用户原脚本。片段包括账号监听入口、子规则、专用策略组、DNS 直连例外、国内域名解析策略和 `direct-nameserver`；其他配置继续来自用户订阅。

写入前保存原脚本和配置快照，拒绝已有同名非本应用策略组；立即重载失败时恢复脚本。备份位于应用数据目录的 `network-backups/`。撤销指定域名的 DNS 配置时移除本应用添加的解析例外，恢复原有策略。Clash 全局脚本需要启用，后续重新激活订阅时会重新生成同一片段。

DNS 首次查询发生在目的 IP 已知之前，因此国内自动识别使用域名集合，IP 路由继续由 Clash 的 GEOIP 等规则判断。域名集合不涵盖全部公司内部域名；例如公共解析只返回内网别名的站点，仍需加入直连域名。

修改连接、直连配置或线路需要先停止运行中的受管环境；配置弹窗在运行期间可查看。现有账号已迁入 Clash 线路并保留原 ID，账号、浏览器和 App 的绑定及登录数据保持不变。旧独立代理进程已停止，其运行代码、组件接口与迁移入口已移除。

## 检测边界

运行中每 500 毫秒检查受管环境，Clash 状态缓存最多 1 秒。发现 TUN 关闭、控制接口失联、规则变化、规则模式退出或活动节点改变后停止受影响环境。它属于发现后停止，存在采样与停止时间差，不是系统 Kill Switch。

TUN 模式下 App 连接显示公网目标是正常现象，不能直接判为绕过代理；保留进程连接样本并标记“已采样”，不将它展示为全量流量无泄漏的证明。系统服务、未知辅助程序、Cowork VM 和更新器仍需要独立实机验收。

直连检测分别检查 Clash 的 DNS 查询和系统到目标 443 端口的连通性；不代表用户已登录或业务操作成功。检测域名只接受已配置的直连域名。

## 验证

本次使用真实本机 Clash 读取版本、TUN 和节点列表；使用独立 Mihomo 实例、两个本机上游验证账号入口分流、公共策略组改变后入口保持、关闭 TUN 拒绝启动、不同出口并发拒绝、异常停止、脚本重复执行及订阅节点消失。没有为这些实验登录 Claude 账号或修改用户实际 Clash 配置。

macOS 本机界面和接口已验证。Windows 提供回环控制接口及配置路径分支，未完成 Windows 实机验收。

# 创建与管理专用代理

在「账号与环境管理 → 代理设置 → 添加代理」选择：

- **已有代理地址**：填写 HTTP、HTTPS 或 SOCKS5 地址，继续由提供该地址的程序管理服务。
- **创建专用代理**：安装 Mihomo 内核，粘贴 Clash 订阅链接或导入 YAML / JSON 配置，读取节点并选择一个，填写名称后创建并启动。

创建后获得固定的 `http://127.0.0.1:端口` 地址。将账号的浏览器和 App 环境绑定到此代理，即可沿用原有启动检查与出口验证。代理页可以启动、停止、检测和编辑节点；环境正在使用代理时，先关闭环境再停止或修改代理。

应用启动时恢复之前开启的专用代理，环境启动时也会确保对应服务已启动。退出应用时，先关闭受管环境，再关闭代理进程。端口冲突、内核启动失败或节点连接失败会保留错误，代理不会切换为系统直连。

## 分流

Claude / Anthropic 及已列入配置的相关服务域名固定走所选节点。其余公网请求默认也走节点。局域网地址、`.local` 与编辑器中的直连域名使用本机连接；默认加入 `sankuai.com`、`meituan.com`、`meituan.net`，可按实际公司网络修改。Claude 服务域名不能加入直连。DNS 使用系统解析器，不修改系统 DNS；公司域名需要本机已连公司网络或 VPN。

仅导入配置中的独立节点，不应用订阅的监听端口、TUN、系统代理、代理组或脚本。依赖其他节点的链式配置需要先整理为可独立连接的节点。订阅在点击「读取节点」时下载，不保存订阅地址，也不自动刷新；更换节点时可重新导入。

## 安装与保存位置

内核从 [Mihomo 官方发布](https://github.com/MetaCubeX/mihomo/releases)下载并与发布记录中的 SHA256 比对，安装在应用数据目录 `proxy-services/core/`。选中节点和生成配置保存在 `proxy-services/entries/代理ID/`，文件权限为当前用户读写；不写入项目源码。服务只监听 `127.0.0.1`，不开启 TUN，不改系统代理设置，也不依赖 Clash Verge 的安装目录。

Mihomo 使用 [GPL-3.0 许可证](https://github.com/MetaCubeX/mihomo/blob/Meta/LICENSE)，副本见 [Mihomo LICENSE](../frontend/public/licenses/mihomo-LICENSE.txt)。安装清单同时记录精确版本、校验值及对应源码链接。

早期由本应用创建的美国专用代理可通过「交给应用管理」接管。接管保留原代理 ID、本机端口与账号绑定，并备份旧启动项；失败时恢复旧服务。普通外部代理不会自动接管。

# DSH 轨迹对齐记录

2026-10-02 对照本机 DeepSeek Harness 桌面包（desktop-runtime 0.2.0-rc.2）的 `dsh-client-ui-trajectory/lib/client.js` 和原生日志核验。应用读取本地历史，不连接 DSH 运行中的会话服务。

## 本次修正

| 原实现偏差 | 修正及对应原生规则 |
| --- | --- |
| 只调用工具的助手消息被丢弃 | 每个已落盘助手步骤保留一个模型单元；无文字时显示“（仅工具调用）”。对应 `expandAssistant` / `summarizeAssistantActivity`。 |
| 思考和回复拆成两个导轨单元 | 一个助手记录内分别展示思考与回复；保留分页原文。 |
| 助手详情缺少工具入口、思考默认收起 | 默认展开已有思考，保留本次消息中的工具名称与参数摘要；按同轮、同步骤、调用 ID 和名称唯一关联后跳转，不猜测歧义关联。 |
| 模型单元没有执行时长 | 使用 `step/start` 到 `assistant/message` 的时间；按原生压缩流重建首 token 时间，展示首 token 延迟、生成时间、吞吐量和 Token 用量。对应 `assistantStreamFirstTokenTime`。 |
| 工具列表只显示完成状态、字符数 | 显示 `→` 与实际结果摘要，失败显示原生错误代码。 |
| 图片只展示路径文字 | 读取日志中的附件引用，在结果和概述中显示 DSH 保存的原始图片；不依赖原文件仍在工作目录。只读校验内容摘要，不接收任意文件路径。 |
| Schema 页固定说没有保存 | 读取调用发生时生效的 `request/header.header.tools`，按工具名取当时的描述和参数定义；不使用最新定义覆盖历史。 |
| 标题缺少步骤编号、层级 | 详情显示轮次、原生步骤与调用层级。 |
| 工具嵌套调用被忽略 | 读取 PTC 开始与完成记录，按原生根调用、父调用、子调用 ID 关联，展示独立参数、结果、时长与失败状态。 |
| 长会话导轨合并抽样 | DSH 保留每条记录的独立导轨标记，分页与全文搜索不改变标记身份。 |
| 收起轮次把助手行和工具行都计作步骤 | DSH 步骤数按原生 step 去重，工具数量单独统计。 |
| 点击收起的工具标记展开所有调用 | 只展开目标工具所在分组，保留其他调用的收起状态，与 `openRecordSummary` 一致。 |
| 重试被忽略或另加一行 | 请求重试归属模型步骤，保留首次尝试的首 token 时间和原始失败详情。 |
| 压缩记录只有一句提示 | 关联压缩开始、摘要和结束记录，展示摘要、模型、用量及真实时长。 |
| 系统提示词被画成绿色上下文 | 系统与工具定义更新使用系统标记；上下文压缩归入模型导轨。 |

## 验证

- 截图“读取设计稿并贴截图”：142 个单元、64 个模型步骤、72 次工具调用。使用桌面包原始 `deriveTrajectoryTimeline` / `deriveTimedTimeline` 函数对比，142 个顺序区间和 142 个压缩时长区间一致。
- 第 55 步 `read_image`：原生参数 Schema、43 ms 时长和 38,536 字节 PNG 附件一致。
- 通过官方 Computer Use 实际检查两个桌面窗口，确认 DSH 原生 64 步统计、思考展开、工具快捷入口；新版应用另行统计 142 条记录。
- 本机 11 条 DSH 会话解析无未知记录警告，11 次 PTC 子调用均有可验证父调用。
- 隔离回归覆盖 v0–v4、Zstandard 拼接帧、跨步骤同 ID、歧义保留、历史 Schema 更新、附件校验、长文本分页、独立导轨和跨页搜索。测试使用合成数据，不提交用户历史。

## 读取边界

已落盘的轨迹可对齐；DSH 正在生成但尚未写入历史的流式内容、内存中的审批与请求状态，需要连接其运行时服务才能同步。这与缺少解析字段是不同问题，不能用推测的数据补齐。当前不改写 DSH 原始日志，不读取认证文件。

不同日志版本按其实际字段展示；缺少计时或 Schema 时显示未记录。图片预览上限 20 MiB，附件丢失或内容校验失败会说明无法读取。
